# План адаптера CADCraft к контрактам RFC-0020

App-local протокол закрыт (ADR-0021 §3): #2934–#2938 закрыты 2026-11-23 как
superseded RFC-0020, открытых PR из форка нет. Ветка `collab/2938-threads`
(`f1119912`) остаётся в `copoka/cadcraft` источником для адаптера. Эта страница —
её инвентарь: что каждый модуль становится под контрактами, какие шесть
поверхностей адаптер обязан закрыть, что есть в общем слое и каким будет первый
инкремент.

Числа строк — `git ls-tree -r` + `wc -l` по `collab/2938-threads` на `f1119912`,
2026-11-23. Это инвентарь кода, а не поставленная голова.

## Шесть поверхностей

1. **Session.** Упорядоченная подача с непрозрачными scope-locks для
   некоммутирующих команд и lock-free путь текста. Сейчас порядок один:
   `Mutex<Room>`, все операции сериализуются; `OpKind` уже различает
   `Command`/`Primitive`/`Structural`, structural принимается только на
   актуальной `baseVersion`, повтор `opId` отвечается из окна, join идёт
   снапшотом частями по 512 KiB. Пробел — scope: цельная блокировка строже
   контракта (два редактора разных сущностей не должны ждать друг друга), и
   passthrough `crdt.*` отсутствует (сегодня его и нет, регрессии не будет).
   Адаптер выводит scope из команды и `context` (пространство + handle/выбор +
   слой) и отдаёт таблицу блокировок общему слою, когда контракт появится.

2. **Presence.** Эфемерный latest-wins на участника: TTL 30 с, роль
   подставляется сервером из JWT до пересылки, в версию/журнал/снапшот не
   попадает (проверено тестами). Проекция — пространство, курсор в мировых
   координатах, выбор, активный слой, вид. Пробел: панель участников рисуется
   самим приложением, а не `craft_ui::presence::PresenceBar` (доступна в
   влитом #160); список участников хоста — #716. Хост-роли —
   `owner`/`editor`/`viewer`; неизвестную (например `commenter` из общего
   контракта хоста) `role_from_host` сейчас не угадывает и оставляет приложение
   одиночным — при подключении #716 её надо свести к `viewer`, не к `editor`.

3. **Texts.** Сейчас текстового пути нет: `text`/`mtext` — команды, создающие
   сущность целиком; правка заменяет сущность (`EntityReplace`), undo хранит
   образы чертежа. RFC-0020 уводит текст на lock-free путь `Texts`. Пробел —
   адресация `(handle, поле)`, CRDT и возврат потерянного текста: если
   структурное удаление выиграло, набранный текст сейчас пропадает, а
   гарантия 1 требует локальной восстановимой копии, показанной пользователю.
   План: поля `Text`/`MText`/`ATTDEF`/`ATTRIB`/override размера; кадры
   непрозрачны для приложения, оболочка сущности (геометрия, слой, стиль)
   остаётся на упорядоченном пути; замена оболочки и правка кадра коммутируют,
   геометрическое удаление выигрывает, текст возвращается копией. В первый
   инкремент не входит: общего `Texts` API нет, #345 — только оракул.

4. **Модель DXF/DWG.** `Drawing` покрывает header, `foreign` (сырые объекты
   файла), слои/типы линий/стили (текст, размеры, выноски, таблицы, мультилинии),
   блоки, model space и layouts, активный layout, виды, VPORTS, UCS, состояния
   слоёв, группы, таблицы печати, constraints, масштабы. Change set закрывает
   сущности одного пространства и порядок отрисовки, записи Layer/Layout/Block
   и определение блока целиком; не закрывает переменные header, типы линий и
   стили, constraints, группы, активный layout, таблицы печати. Идентификаторы —
   файловые `Handle`: уникальны, переживают round-trip, не переиспользуются.
   Несмоделированное: DXF пишет сырые объекты обратно; запись DWG теряет
   неизвестные типы, DXF ≥R2013 — SAT-текст, и это уходит в `not_saved`.
   Правило адаптера: реплики меняют чертёж только change set'ом и никогда не
   перекодируют часть файла, которую не моделируют.

5. **Commit кабинета.** Комната пишет файл из авторитетного чертежа
   (`CommitFormat::{Dxf,Dwg}`) и шлёт `{fileId, name, bytes, sha256, version,
   expectedVersion}`; `expectedVersion` — etag прошлого принятого коммита, `409`
   не перезаписывает, а оставляет файл для «сохранить копию»; `not_saved` идёт
   в предупреждение и аудит кабинета (ADR-0009); commit готовится вне
   блокировки комнаты, повтор той же версии отвечается из памяти, etag переживает
   рестарт. Пробел — словарь: локальные `CabinetConfig`/`Published` вместо
   влитого `craft_cloud` (`Entry::etag`/`writable`, `Event::Saved`,
   `Fault::Conflict`, #160 `fd7232d7`). Это маппинг, а не второй протокол.
   Сам endpoint кабинета — вне репозитория (`deployment.md`, дыра P0).

6. **Роли.** JWT HS256 → `sub`; `Role::{Owner,Editor,Viewer}`; сервер
   подставляет роль в presence и отказывает viewer'у в `policy` до движка (гейт
   UI — вежливость, не гейт); deny-list файловых/UI/скриптовых команд; лимиты
   1 MiB / 5 000 объектов / 8 участников. Пробелы: `may_close` есть у роли, но
   сообщения закрытия комнаты в конверте нет; JWT (с обязательным `exp`)
   проверяется на handshake, отзыв токена открытый сокет не выбивает — «место
   отозванного» контракту ещё нужно; сами роли определены в session-контракте,
   которого нет, и приложение не должно оставаться единственным гейтом.

## Первый инкремент

Ветка от `origin/main` `6601baf6` (`feat/collab-adapter-cadcraft`), только
сторона приложения, без изменения протокола, **не более 1 500 строк** новой
работы. Закрытая ветка не мержится: 697 позади и 75 впереди `origin/main`;
слияние притащило бы двухмесячный дрейф и историю закрытого PR. Ядро переносится
выборочно (`git show collab/2938-threads:<path>`), отдельными коммитами, не
внутри инкремента.

1. Минимальное ядро `crates/collab` (~900): `change.rs`, `apply.rs`, `diff.rs`,
   `table.rs`, `context.rs`, `error.rs`, `lib.rs` с `f1119912`, адаптированные к
   нынешнему API `doc` (проверено на `origin/main`: `entity`/`modify_entity`/
   `remove_entity`/`space_mut`/`space_of`/`bump_handseed`,
   `EntityStore::{push, move_next_to, neighbours}`), плюс строка уровня L2 в
   `xtask layers`. Без wire, сервера, клиента и cmdline.
2. `crates/collab-commit` (L5, ~140): `CommitPlan { version, bytes, not_saved }`
   и `may_publish` — `not_saved` считается через `engine::cmd::file::loss_on_save`
   (неизвестные типы в DWG, SAT-текст в DXF ≥R2013) и непустой никогда не
   становится молчаливой публикацией.
3. Conformance-набор (~300) из `crates/collab/src/tests.rs` и сценариев
   `rfc.md` §11: две реплики сходятся; rename
   слоя переписывает ссылки во всех пространствах и блоках; создание/удаление
   блока едет определением целиком; якоря порядка (`Bottom`/`Top`/`After`/
   `Before`); `foreign` не трогается change set'ом; `not_saved` блокирует
   публикацию.
4. `docs/collab/adapters.md` и запись в `STATUS.md` (~150).

Бюджет: ядро 900, commit 140, тесты 300, документация 150 — около 1 490.

Вне инкремента: `Texts` (ждёт общего API и вердикта по #345), scope-locks,
бамп `craft-ui` до presence-бара, замена пина #716 на влитую ревизию, маппинг
кабинета на `craft_cloud`. Второй инкремент — impl общих session/presence
трейтов, когда появится контрактный PR; затем перенос `Room`/`net`, клиентского
`driver` и UI-гейта.
